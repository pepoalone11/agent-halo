## AI Diary

I made the right architectural decision to compose the full catalog from layers instead of manufacturing 53,760 state strips, but I initially made an important visual mistake: I treated “supports every combination” as permission to replace the character's established motion grammar with generic whole-container CSS transforms. The implementation was mechanically coherent and extensively tested, yet the result looked wrong immediately to Mahiro. That distinction matters. Tests could prove that all four layers existed, IDs normalized, selectors persisted, and states rendered, but they could not prove that Idle felt like Pixabots. Once Mahiro called it out, the correct evidence was already in reach: upstream's per-layer bounce and the tracked approved rig. I should have started there rather than inventing a simplified bob. The same lesson repeated for Working, where whole-body rotate/translate read as a shaken sticker instead of articulated pixel motion. I am satisfied that I corrected both quickly and retained the scalable layered architecture, but the unnecessary install-review-repair loop was avoidable. With a +50% weekly local session trend, preserving quality while moving fast matters more than merely completing more loops. The best outcome here came from combining repo truth, direct human visual judgment, and narrow mechanical verification rather than allowing any one of them to stand in for the others.

## Honest Feedback

Three friction points stand out. First, I implemented state motion before faithfully mapping the source motion contract. That was overconfident: “layered runtime” solved asset scale, not motion taste. Second, the first tests asserted animation names and asset paths but not the structural ownership of motion; they allowed a whole-body animation to pass when the required behavior was per-layer articulation. The repaired tests now make that distinction explicit. Third, provenance was initially internally inconsistent because the old builder, receipts, and active docs still described ten loadouts and 50 strips. The scout and verifier caught important drift, but I should have included the text-contract migration in the original implementation plan rather than cleaning it after code was already working. Browser instability also produced two target-crash failures late in validation; retrying only those exact unrelated cases was the correct response, but serial browser discipline remains important. The final implementation is stronger, yet the session would have been shorter and more trustworthy if source motion fidelity and current-text ownership had been first-class acceptance criteria from the start.

## Lessons Learned

- A scalable layered renderer must preserve the source character's layer-specific motion grammar; whole-container transforms are not an equivalent shortcut.
- Motion tests should assert the animated owner (body container versus each part layer), not only that an animation exists.
- Complete-catalog migrations require code, native validation, runtime assets, manifests, provenance receipts, active docs, and performance budgets to change together.
- Human visual acceptance can falsify a mechanically passing motion implementation; install/review evidence remains distinct from automated checks.
