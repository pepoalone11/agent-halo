## AI Diary

I felt the main risk in this session was not raw implementation complexity but ownership drift across renderer, native window state, camera runtime, Pomodoro state, and current documentation. The first implementation could easily have looked correct while leaving a stale completion summon able to dismiss a manually pinned companion, or while allowing a replay animation to accidentally become the semantic truth. I became more disciplined once I treated the Pet as a projection surface and made the main renderer remain the only Pomodoro and notification owner. The review cycle was valuable because it exposed small but real contract gaps: initial projection needed to be atomic, repeated Open Focus requests needed an identity that could retrigger native foreground focus, and even a 2px overflow mattered for the native hitbox contract. I also noticed that final Goal bookkeeping became much noisier than the actual engineering work. The structured evidence was useful, but the runtime correctly refused to let me claim human-owned criteria even after I recorded Mahiro's direct confirmation. I should keep respecting that boundary instead of manufacturing closure. With a +200% derived weekly session change, the momentum is strong, but the important achievement is that the installed artifact, source checks, independent review, and Mahiro's real-camera experience all converged on the same result.

## Honest Feedback

Three friction points stood out. First, the Goal API has no agent-callable way to record a direct human verification as verified; `user` evidence can be attached, but completion still remains blocked, so the final control must stay with Mahiro or the Goal UI. Second, the initial Rust suite was run with parallel test threads and surfaced an unrelated local-services race; the mission's serialized validation rule should have been applied from the first full run, not only on the retry. Third, the feature crossed enough state owners that a narrower early contract table would have prevented several review repairs. The implementation was eventually strong, but the route there included too much bookkeeping output and repeated evidence mutations. Next time I should establish one evidence map before the final gate, run the exact release-equivalent serial commands once, and reserve the conversation for decisions and actionable checkpoints rather than exposing internal ceremony.

## Lessons Learned

- Manual visibility ownership must be attempt-scoped; a stale automatic dismissal may never hide a newer pinned companion.
- Presentation overrides and replay acknowledgements must not mutate truthful semantic state, Signal, or keep-awake decisions.
- A native focus request needs a replay identity when identical user actions must retrigger foreground and DOM focus.
- Camera permission remains safest when chooser/launcher surfaces are camera-free and only an explicit exercise selection starts the stream.
- Human acceptance evidence is not permission for an agent to self-verify a human-owned Goal criterion.
